External Integration Documentation
==================================

This document describes the Command-Line Interface (CLI) integration for running the application externally, including all available parameters, output formats, and default level IDs.

================================================================================
CLI PARAMETERS
================================================================================

All CLI parameters are optional. When no parameters are provided, the application runs in normal interactive mode.


BASIC PARAMETERS
----------------

--level <levelId>
    Description: Run a specific level by ID. The application will start with a limited navigation menu and automatically load the specified level.
    Example: --level begint
    Notes:
        - Mutually exclusive with --calibrate-only
        - If the level is not found, the application will display an error and exit with code 4
        - The application will automatically close 15 seconds after level completion

--output <filePath>
    Description: Specify the output path for session results JSON file. All relative paths are resolved relative to the current working directory.
    Example: --output ./results/session-output.json
    Default: session_results.json (if not specified)
    Notes:
        - Required for exporting session results in external mode
        - Directory will be created if it doesn't exist


CALIBRATION PARAMETERS
----------------------

--calibration-data <filePath>
    Description: Path to a JSON file containing calibration data to load. All relative paths are resolved relative to the current working directory.
    Example: --calibration-data ./calibration/my-calibration.json
    Notes:
        - Required when using --skip-calibration
        - Calibration data will be applied immediately if --skip-calibration is used
        - Otherwise, calibration data is loaded but not applied until user enters calibration mode or starts the level

--skip-calibration
    Description: Skip the calibration requirement by using pre-loaded calibration data.
    Example: --skip-calibration --calibration-data calibration-test-data.json
    Notes:
        - Requires --calibration-data parameter
        - Calibration data is applied immediately on load
        - Allows headless mode to work (headless mode requires --skip-calibration)

--calibrate-only
    Description: Run the application in calibration-only mode. The application will open to the calibration screen and allow exporting calibration data.
    Example: --calibrate-only --output ./calibration.json
    Notes:
        - Mutually exclusive with --level
        - Use the "Complete Calibration" button to export and exit
        - Calibration data is exported to the path specified by --output (or current working directory if not specified)

--calibration-time <seconds>
    Description: Set a time limit (in seconds) for calibration. A countdown timer will be displayed. If the timer reaches 0 before the level starts, the application closes with exit code 2.
    Example: --calibration-time 300
    Default: -1 (disabled, infinite time)
    Notes:
        - Must be an integer >= -1
        - Setting to -1 disables the timer (or don't specify the parameter)
        - Timer is displayed at the top of the screen in HH:MM:SS format

--pause-time <seconds>
    Description: Set a time limit (in seconds) for pause duration during active gameplay. A countdown timer will be displayed while paused. If the timer reaches 0, the application closes with exit code 3.
    Example: --pause-time 120
    Default: -1 (disabled, infinite pause time)
    Notes:
        - Must be an integer >= -1
        - Setting to -1 disables the timer (or don't specify the parameter)
        - Timer only counts down while the game is paused
        - Timer is displayed at the top of the screen


AUDIO PACK PARAMETERS
---------------------

--audio-pack <packId>
    Description: Pre-select an audio pack to use for the level. This setting can be overridden by the level's own audio pack specification.
    Example: --audio-pack my-custom-pack
    Notes:
        - Audio pack priority order:
          1. Level's audioPackId (if exists and pack is found)
          2. CLI --audio-pack (if provided)
          3. Default pack
        - Pre-loaded levels never use the audio pack selected in the Content Library
        - If a level specifies a custom audio pack that doesn't exist, falls back to CLI pack or default


ADVANCED PARAMETERS
-------------------

--headless
    Description: Run without UI (advanced, for automated testing). Navigation is hidden, only essential feedback is shown.
    Example: --headless --level begint --skip-calibration
    Notes:
        - Requires --skip-calibration to be enabled
        - Level will automatically start with no user input required
        - If calibration is required, headless mode will result in an error and exit
        - Primarily intended for automated testing scenarios

--validate-level <levelId>
    Description: Validation mode. Check if a level exists and is valid. If the level specifies a custom audio pack, ensure that audio pack exists as well.
    Example: --validate-level begint
    Notes:
        - Mutually exclusive with other run modes (--level, --calibrate-only)
        - Exits with code 0 if valid, code 5 if invalid
        - Validation results are sent via IPC before exit


PARAMETER COMBINATIONS
----------------------

Valid combinations:
    - --level with --output, --calibration-data, --skip-calibration, --calibration-time, --pause-time, --audio-pack
    - --calibrate-only with --output
    - --validate-level (standalone)
    - --headless with --level, requires --skip-calibration

Invalid combinations:
    - --level with --calibrate-only
    - --calibrate-only with --level
    - --validate-level with any other run mode
    - --headless without --skip-calibration
    - --skip-calibration without --calibration-data



================================================================================
EXIT CODES
================================================================================

The application uses standardized exit codes to indicate completion status:

0 - Success
    Level completed successfully, or validation passed

1 - User Closed
    User manually closed the application window (not a programmatic exit)

2 - Calibration Timeout
    The calibration timer (--calibration-time) reached 0 before the level started

3 - Pause Timeout
    The pause timer (--pause-time) reached 0 while the game was paused

4 - Level Not Found
    The specified level ID was not found or is invalid

5 - Error
    General error condition, including:
    - Pre-flight checks failed (webcam unavailable, missing dependencies)
    - Level structure validation failed
    - Export failed
    - Validation failed
    - Other runtime errors



================================================================================
SESSION OUTPUT JSON FORMAT
================================================================================

When a level completes in external mode, session results are exported to a JSON file. The file structure is as follows:

{
    "sessionId": "uuid-string",
    "timestamp": "2024-01-01T12:00:00.000Z",
    "levelId": "begint",
    "levelTitle": "Beginner Training",
    "completionStatus": "completed",
    "completed": true,
    "score": 1250,
    "totalTime": 420,
    "sessionStats": {
        "loads": 3,
        "dives": 15,
        "holdTime": 45,
        "penalties": 2
    },
    "taskDetails": [
        {
            "taskType": "hold",
            "completed": true,
            "score": 300,
            "summary": {
                "type": "hold",
                "desc": "Hold at depth 2 for 10 seconds",
                "targetDepth": 2,
                "counts": {
                    "perfect": 2,
                    "pass": 1,
                    "fail": 0,
                    "penalties": 0
                },
                "totalTimeHeld": 30,
                "score": 300
            }
        },
        ...
    ]
}


FIELD DESCRIPTIONS
------------------

Top-level fields:
    sessionId: Unique identifier for this session (UUID format)
    timestamp: ISO 8601 timestamp of when the session completed
    levelId: The ID of the level that was run
    levelTitle: Human-readable title of the level
    completionStatus: Status string indicating how the session ended
        - "completed": Level completed successfully
        - "user_closed": User manually closed the application
        - "calibration_timeout": Calibration timer expired
        - "pause_timeout": Pause timer expired
        - "error": An error occurred during execution
        - "level_not_found": The specified level was not found
    completed: Boolean indicating if the level completed successfully
    score: Final score achieved in the level
    totalTime: Total play time in seconds

sessionStats:
    loads: Number of successful loads completed
    dives: Total number of dives (from updown and hitdepth tasks)
    holdTime: Total time held at depth in seconds
    penalties: Total number of penalties incurred

taskDetails:
    Array of task summary objects, one for each task type encountered:
    taskType: Type of task (e.g., "hold", "updown", "hitdepth", "clap")
    completed: Boolean indicating if the task was completed
    score: Points earned from this task type
    summary: Detailed summary object containing:
        - type: Task type
        - desc: Task description
        - counts: Object with perfect, pass, fail, and penalties counts
        - totalTimeHeld: (for hold tasks) Total time held in seconds
        - score: Points earned
        - Other task-specific fields

CUSTOM LEVEL IDs
----------------

Custom levels can be created using the Level Editor in the application. Custom level IDs are typically in the format:
    custom-<timestamp>

To find custom level IDs:
    1. Open the application in normal mode
    2. Navigate to the Level Editor
    3. The Level ID is displayed in the Preview section
    4. Or use browser console: JSON.parse(localStorage.getItem('custom_levels'))



================================================================================
USAGE EXAMPLES
================================================================================

Run a single level:
    npm run electron -- --level begint --output results.json

Run a level with calibration data:
    npm run electron -- --level begint --calibration-data cal.json --skip-calibration --output results.json

Run a level with time limits:
    npm run electron -- --level begint --calibration-time 300 --pause-time 120 --output results.json

Run in headless mode (automated testing):
    npm run electron -- --level begint --headless --skip-calibration --calibration-data cal.json --output results.json

Validate a level:
    npm run electron -- --validate-level begint

Run calibration-only mode:
    npm run electron -- --calibrate-only --output calibration.json



================================================================================
NOTES
================================================================================

- All relative file paths are resolved relative to the current working directory (where the CLI command is executed)
- The application automatically closes after level completion with a 15-second delay
- Countdown timer is displayed in external mode showing remaining time before close
- Pre-flight checks verify webcam availability and required dependencies before starting
